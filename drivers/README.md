# 驱动目录规划

按子系统组织目录，不按“是否能作为字符设备访问”划分所有硬件。
块设备和字符设备是上层访问抽象；存储、输入、显示、网络是硬件职责。

## 当前布局

```text
drivers/
├── bus/                 总线枚举、配置与设备发现
│   └── pci/             PCI 总线
├── block/               通用块设备层
│   ├── blk_dev.c        扇区缓存、引用管理、块读写
│   └── disk.c           disk_* 兼容接口
├── storage/             存储控制器与硬盘传输驱动
│   └── ahci/            SATA AHCI
├── char/                通用字节流设备与终端
│   └── tty/             终端接口、终端队列
├── input/               输入设备
│   └── keyboard/        当前键盘驱动
└── video/               显示设备
    ├── vga/             VGA
    └── svga/            SVGA
```

`block` 不负责操作 AHCI 寄存器；`storage` 不负责文件系统解析。
当前块层仍直接调用 AHCI，目录调整没有引入多后端注册机制。
后续支持第二种存储后端时，应先增加块设备结构与 read/write/flush 操作表，
由各后端注册设备，再让缓存按设备和扇区号索引。

## 后续驱动的归属

| 目录 | 放置内容 |
| --- | --- |
| `block/` | 块设备注册、请求分发、通用缓存 |
| `storage/ata/` | IDE/PATA 控制器与 ATA PIO/DMA 传输 |
| `storage/nvme/` | NVMe 控制器、队列与命名空间 |
| `storage/scsi/` | SCSI 命令与磁盘支持 |
| `storage/virtio_blk/` | VirtIO 块设备后端 |
| `char/serial/` | UART、串口字节流设备 |
| `char/misc/` | null、zero 等简单字符设备 |
| `input/` | 键盘、鼠标、触摸与输入事件层 |
| `video/` | 显示控制器、帧缓冲与模式设置 |
| `net/` | 网卡驱动；协议栈应独立于驱动目录 |
| `audio/` | 声卡、音频控制器 |
| `usb/` | USB 主机控制器、枚举与公共传输支持 |
| `bus/` | PCI、平台总线及通用设备匹配 |
| `virtio/` | VirtIO 公共传输与 virtqueue；具体设备放对应子系统 |
| `platform/` | 不适合归入其他子系统的平台专用设备 |

未来 USB 键盘放 `input/`，USB 存储放 `storage/`，共享 USB 传输放 `usb/`。
PS/2 控制器若需要键盘和鼠标共享，可提取到 `input/serio/`。
暂不为尚未实现的驱动创建空目录或加入构建。

## 与其他目录的边界

- `fs/`：文件系统、分区解析（现有 MBR）、挂载逻辑。
- `mm/`：DMA 所需内存分配、页表与 MMIO 映射，不放设备寄存器协议。
- `arch/`：架构启动、中断控制器、CPU 定时器等架构相关支持；本次不迁移。
- `include/`：保持现有公开头文件路径，避免同时改变调用方接口。

## 命名与构建规则

目录与文件使用小写和下划线；优先使用明确的子系统名或标准缩写。
每个参与构建的目录保留 Makefile，父目录通过 `obj-y += 子目录/` 引入。
同一硬件驱动较小时可保留一个 `.c`；变大后再拆分为寄存器定义、队列和传输实现。
私有头文件与实现同目录，跨子系统公开接口才放到 `include/`。

本次仅移动源码并调整构建，不改变驱动行为。旧目录可能仍有历史 `.o`
文件，它们不再被新 Makefile 引用；不要将这些构建产物当作源码布局。
首次在支持的构建环境验证时，应清理旧构建产物再完整编译。
